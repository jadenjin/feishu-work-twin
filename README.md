# Feishu Work Twin

本地飞书工作数字人：使用个人账号接收消息，通过 ChatGPT 账号登录的 Codex CLI 处理会话，并提供本机网页工作台。

基于 [cv-cat/LarkAgentX](https://github.com/cv-cat/LarkAgentX) 二次开发。保留原项目历史与协议实现，原始说明见 [README.upstream.md](README.upstream.md)。

## 功能

- 私聊根据语境自动回复；群聊默认不自动回复，可逐群选择闲聊模式、仅 @我、仅 @全体或关闭。
- 连续短句按最后一句后的停顿合并；群里单独 @本人时带上同一话题的前文和近期图片。
- 每个联系人、群聊可独立设置自动回复、仅草稿或关闭。
- 人工发送后，该会话暂停自动回复，默认 2 分钟，可在数字人设置调整（0 为关闭）；暂停期间的新消息按最后一次活动延长计时，旧消息不会到期补发。
- 会话概览、有效记忆、联系人角色与回复风格、异常与待办管理。
- 网页支持图片、表情包、图文消息显示，以及图片选择、粘贴、拖入、混排和发送前预览。
- AI 回复润色、文字尾缀、执行记录、左下角数字人入口及居中聊天窗口。
- 数字人控制台可查询工作、创建或完成待办，以及按明确指令发送消息；已建立的会话才能作为收件人。

## 安装与启动

需要 Python 3.11+、[uv](https://docs.astral.sh/uv/) 和已安装的 Codex CLI。

```powershell
git clone https://github.com/jadenjin/feishu-work-twin.git
cd feishu-work-twin
Copy-Item .env.example .env
uv sync --locked
codex login
uv run lark auth qr
uv run lark web --port 8765
```

打开 http://127.0.0.1:8765/。Windows 也可运行 `start-workhub.ps1`；已运行时不会启动第二个监听实例。

`.env.example` 默认使用 Codex 后端、独立会话上下文、群聊默认不回复、不自动标记已读。若 Codex 不在 PATH，填写 `.env` 中的 `LARKX_CODEX_PATH`。模型可通过 `LARKX_CODEX_MODEL` 配置，留空使用 CLI 默认模型。

网页只绑定 `127.0.0.1`。凭证、消息数据库、图片缓存与模型会话保存在 `LARKX_HOME`，默认 `~/.larkx`。这些数据不纳入 Git。不要同时启动 `lark listen --agent` 与网页监听，否则可能重复处理消息。

在“数字人设置”可调整消息停顿时间（0.1–30 秒）和最长等待时间（0.1–60 秒），保存后下一批消息生效，重启后保留。未在网页设置时，`LARKX_BATCH_DELAY` 默认 1.5 秒，收到新句子后重新计时；`LARKX_BATCH_MAX_WAIT` 默认 5 秒，避免连续来消息时一直等待。一个批次最多 20 条。群聊按各群的回复选项触发；选择仅 @我或仅 @全体时，短暂等待期间的未 @补充句会一起理解，其他群消息不会独立触发回复。

## 操作

进入“会话与记忆”选择联系人，编辑消息后点击发送。Enter 换行，Ctrl + Enter 发送。图片最多 6 张，单张不超过 10 MB，支持 PNG、JPEG、GIF、WebP。

“角色档案”设置关系、背景、口吻与独立回复开关。“数字人设置”配置本人工作原则和文字尾缀；尾缀留空可关闭。AI 润色生成的草稿需要手动发送。

待办、会话、角色档案和执行记录支持分页，每页可选 10、20 或 50 条；切换筛选条件后回到第一页。待办和执行记录从服务端分页读取，可查看较早记录。角色档案支持姓名、角色、背景搜索和联系人/群聊筛选，同页翻页与筛选保留未保存的角色编辑。

设置按“回复习惯、自动处理、工作资料、运行状态”分类折叠，默认展开回复习惯。回复习惯与自动处理统一点击“保存回复设置”，工作资料单独保存。项目资料也可逐项展开，折叠不会清空编辑内容；必填项校验失败时会展开对应区域。

### 一键了解工作内容

在“数字人设置 → 工作资料”点击“从聊天发现项目”，从已归档和未归档的聊天中选择相关项目，也可以手动添加项目名称、本机代码/文档目录和别名。展开项目，再展开“用于回复哪些会话”，选择可使用该项目资料的联系人或群聊；未选择会话的项目只整理档案，不参与自动回复。

候选项目再次点击即可取消选择，“移除”后也能重新选择；同页取消再恢复会保留未保存的编辑。会话支持逐项勾选/取消、搜索、全选和清空，搜索时批量操作只影响筛选结果。发现项目只读取候选，不会提前保存表单；选择或取消后点击“保存资料与档案”生效，“一键了解工作内容”也会先保存当前选择。

点击“一键了解工作内容”会先保存配置，再从本机 Codex 已归档、未归档聊天整理职责、负责模块、近期事项和待确认信息。两类记录按会话编号去重，每个项目最多处理最近 30 条匹配聊天中的近期问答。先按项目语境筛选工作原文片段，再整理档案；足球、娱乐、生活、闲聊及与项目无关的个人学习等不纳入，同一聊天或消息混有工作与生活内容时只提取工作部分。筛选片段必须能够逐字对应源消息，没有相关工作证据时不生成新职责，保留原档案。只为实际采用的工作聊天保留来源会话编号及归档状态；不读取工具输出、推理记录或开发者指令。整理在后台运行，可以离开页面，重新进入会显示进度和结果。生成后的档案可手动修改并保存；手动修正会作为后续整理的优先参考，整理期间发生的编辑不会被后台结果覆盖。

整理页面显示已运行时间、当前项目、批次、筛选/总结/合并阶段及已保存项目数。每个项目完成后立即保存并展示，某个项目失败会继续处理其余项目；取消或重启不会丢掉此前已保存的项目。可点击“取消整理”停止本次任务，之后重新提交；重新提交会按当前配置重新整理，不会续接中断的批次。模型调用和排队有超时限制，不会无限等待。模型给错消息序号时，仅允许通过同一聊天内唯一匹配的原文纠正定位；被改写或无法核对的片段不会作为证据，单个无效片段不再导致整批作废。

默认来源是 `$CODEX_HOME/archived_sessions` 和 `$CODEX_HOME/sessions`（包含日期子目录），未设置 `CODEX_HOME` 时使用 `~/.codex` 下的对应目录。两类目录可分别配置，旧版只保存归档目录的设置自动补上同级 `sessions` 目录，其中一类目录不存在不影响读取另一类。匹配依据是聊天记录中的项目目录，并不自动继承当前 Codex 桌面聊天工具；项目目录相同也不代表聊天内容都属于工作，整理前仍会筛选。代码搬迁时，在项目的“工作聊天来源”中保留旧目录，上方代码目录填写新位置。已失效目录仍可用于匹配旧聊天，但不能用于实时检索。

自动回复和 AI 起草会先结合当前会话判断是否需要检索，按需读取指定项目中的代码、Markdown 和纯文本资料，并附带文件位置、行号和修改时间作为模型依据。读取尊重 Git 忽略规则，排除凭据文件、隐藏目录、依赖与构建产物，不跟随目录外链接，不执行资料中的命令；模型本身仍禁用文件和工具访问。单次最多检索两次，每次最多返回四个片段，并限制扫描时间和数据量。检索失败或模型判断依据不足时只留审核草稿，沿用全局暂停、人工接管和群聊开关。尚不解析 Word/PDF、图片或在线飞书文档；源码和历史档案也不能证明当前生产部署状态。

控制台的明确发送指令会执行。发送结果无法确认时保留为待核对，不自动重发；提交相同请求 ID 不会再次发送。实际编码、排期、审批等工作不会仅凭聊天请求被标记为已完成。

### 后台如何处理工作

1. 飞书消息先按消息 ID 入库去重，再按会话与话题进入队列。连续短句合并理解，不把不同发送者的身份混在一起。
2. 人工接管或联系人关闭自动回复时，只整理工作信息，不再为最终不会发送的回复调用项目检索。全局“暂停自动回复”仍保留生成审核草稿的语义；发送前会再次检查接管状态、回复开关和资料授权变化。
3. 分析只读取到本批最后一条消息为止的近期记录，不提前使用下一批排队消息。更新概览按话题拆分，保留原消息时间；超过 20 条的观察批次继续分批处理。手动“更新概览”只更新概览，不因重新分析历史消息而补建待办或记忆。
4. 职责档案帮助理解“哪些工作属于我”，但不代表本人接受了每个相关请求。新任务、旧任务补充、需要本人决定分别处理；普通信息缺项先澄清，不因资料不足一律制造决策待办。
5. 技术回复按收件会话的授权项目查代码或文档；只澄清缺项、寒暄与一般沟通不要求代码证据。历史职责和本地代码不作为已上线、已验收或排期承诺的证明。
6. 待办操作按 ID 查询，不受列表分页和最近 300 条展示上限影响。本人查询待办时先选未完成项，优先展示需要决定与高优先级事项，并提供真实总数；不会因为最近已完成记录过多而遗漏老待办。

在数字人控制台可问“我负责哪些项目”“查看 DTU 的 syncTraffic 实现”“整理我当前需要决定的事项”。只读查询会取得已配置的职责摘要和项目文件依据；名称或别名不明确时不猜测跨项目检索。新增的上下文读取不额外调用模型、不缓存生成答案，文件每次按需读取，返回文件位置、修改时间和截断标记。职责档案仍需手动编辑或通过“一键了解工作内容”更新，并不自动反映项目最新进度。

只读追问会参考最近三个已完成的只读问答，限制长度，并以本轮文件证据为准。资料配置变化后停止引用旧问答；历史中的发送、修改指令不进入本轮授权。执行发送或修改的指令仍需在本轮说清楚对象和内容，不自动沿用本人私有资料的查询结果。

本人查询可以看到所有已配置项目；发给他人的内容只允许使用对应会话授权资料。本人完整工作资料不会注入可执行发送的控制台计划。当前接入范围是选定的本机项目代码、文本资料、工作聊天整理出的职责，以及本机已同步的飞书事项；在线飞书文档、日历、审批和项目管理系统尚未接入。

## MCP 接入

启动工作台后，本机 MCP 地址为 `http://127.0.0.1:8765/mcp`，传输方式选 **Streamable HTTP**。MCP 与网页共用同一个飞书连接，不需要重新登录。当前只供本机应用访问，不支持云端应用直接连接。

仅支持 stdio 的应用，可参考 [mcp-config.example.json](mcp-config.example.json) 配置命令，修改为自己的 uv 和项目路径。实际启动命令为：

```powershell
uv run --directory E:\Myproject\LarkAgentX --no-sync python -m larkx.workhub.mcp_server
```

工作台使用其他端口时，在命令最后添加 `--hub-url http://127.0.0.1:其他端口`。

提供 `get_status`、`search_conversations`、`get_chat_history`、`search_messages`、`get_work_context`、`send_message` 六个工具。记录来自本机已同步的数据库，并非飞书全部历史；查询返回 `next_before_id` 可翻页，会话搜索使用 `next_offset` 翻页。

`get_work_context` 是只读工作资料入口，REST 对应 `GET /api/integration/work-context`。不传参数时返回项目目录、职责摘要和最多 20 条未完成事项；用 `project_id` 和 `query` 查询指定项目当前文件。一次最多查两个项目，每个返回两个片段，并标明资料时间、扫描限制和未完成任务总数。多项目无法明确选择时返回 `selection_required`；职责概览仍可依据摘要回答，需要技术依据时再明确项目。

为本人查询可省略 `chat_id`，返回 `scope=owner`；为其他人起草或回复必须传入收件 `chat_id`，返回 `scope=recipient`，只读取该会话授权的项目。不能把本人范围的结果直接转发给他人。此接口不调用模型、不发送消息、不修改任务；调用方已有模型可直接使用这些依据，避免再次让另一个模型整理整份历史。

先搜索联系人或群聊，取得明确的 `chat_id`，再发送。重名会返回多个会话，不自动猜测。发送需指定消息正文和唯一 `request_id`（建议 UUID），同一发送的重试必须复用 ID。仅 `status=sent` 表示成功，`uncertain` 应先在飞书核对，不换 ID 重发。发送沿用设置中的文字尾缀，写入执行记录，并触发配置时长的人工接管（默认 2 分钟）。

客户端提示示例：“查边泽文最近 30 条聊天记录”“搜索关于上线排期的消息”“给边泽文发送：下午三点开会”。请在客户端启用发送工具的确认提示。

MCP 协议实现使用 [官方 Python SDK](https://github.com/modelcontextprotocol/python-sdk)。

## 实现与限制

`larkx/workhub` 包含 FastAPI 本地服务、SQLAlchemy 状态存储和前端静态文件；`CodexBackend` 使用独立临时目录与只读沙箱生成结构化分析。

个人账号消息通道依赖飞书网页私有协议，后续飞书更新可能影响登录、消息或资源上传；该项目并非飞书官方客户端。聊天历史与必要图片会作为模型上下文提交到已登录的模型服务。仅在本机环境使用，勿把控制台直接暴露到公网。

群聊“闲聊模式”会让 AI 结合上下文判断是否参与：优先回应对我说的话，别人之间的讨论通常不接话，有趣或能补充信息时可偶尔插一句，并非每条都回复。闲聊模式下真实 @我（包括单独一个 @）必须回应，仍遵守人工接管、全局暂停和独立关闭开关。

群聊定向回应支持引用消息和真实 @个人。AI 使用当前群聊/话题中的消息 ID 和发送者 ID 选择对象，普通插话可以不指定。MCP `send_message` 可选参数 `reply_to_message_id` 与 `mention_user_id`，引用对象和 @对象会纳入重复请求校验。已在三人群实测发送，服务器回读确认引用关联和真实 @用户 ID。

Codex 失败提示会区分网络、登录、模型、额度和格式问题。仅网络错误在同一次总超时内重试一次，飞书消息仍只在成功生成后发送。结构化分析直接使用工作台提供的最新上下文，不重复拼接过去的完整背景快照。

待办按具体事项关联：AI 通过已有任务编号将后续分句、解释、附件和进展追加到同一条待办；不同问题分别建单。关联限制在当前会话和话题的未完成任务内，保留人工编辑的标题、状态、日期及草稿。相同消息批次重复分析不会重复建单；同一会话的回复分析和后台整理按顺序执行。私聊和群聊均提供本人用户 ID，后台整理不生成自动回复。

数字人设置中的“人工接管等待”按分钟配置，范围 0–1440 分钟，默认 2 分钟，0 关闭。对话持续期间，以双方最后一次消息重新计时；修改设置会按最后活动时间更新仍在暂停的会话，已经结束的暂停不会重新开启。到期后仅对后续新消息恢复自动回复，暂停期间的旧消息不会补发。

Codex 可执行文件先检查 `LARKX_CODEX_PATH`，失效时查找 PATH；Windows 下还会查找本机 Codex 应用安装目录。应用更新移除旧版本后，下次调用会重新定位 CLI，不依赖固定版本目录。
